# Adventure engine spec (v1)

Owner: Opus (design). Implementers: subagents. Read docs/ADVENTURE.md for the game design.
Plain JS classic scripts (no modules, no fetch, no getImageData in shipped code) so index.html works on file:// and on GitHub Pages.

## Files
- `src/adv-world.js`: world model, chunk loading, heights, collision, autotiling. Global `ADV`.
- `src/adv-render.js`: overworld renderer (terrain, sorted drawables, camera).
- `src/adv-scene.js`: `AdventureScene` (input, player, follower, camera follow). Hooked into `MenuScene` as an "Adventure" item.
- `data/adv/tileset.js`: `window.ADV_TILESET` (real art, built by `tools/adv-build-tileset.py`).
- `data/adv/tileset-placeholder.js`: `window.ADV_TILESET_PLACEHOLDER`, same schema, flat coloured tiles drawn into an offscreen canvas at startup. Engine uses `ADV_TILESET || ADV_TILESET_PLACEHOLDER`.
- `data/adv/chunks/<cx>_<cy>.js`: one file per chunk, each calls `ADV.chunk(cx, cy, data)`.
- `data/adv/world.js`: `window.ADV_WORLD = { name, chunksW, chunksH, spawn: { x, y } , towns: {...} }`.
- `tools/adv-build-testworld.mjs`: writes a procedural test world into data/adv/ (until the real region exists).
Reuse core.js helpers (clamp, img, preload, INPUT, AUDIO, dirFromVec, DIR_VEC) and battle.js sprite helpers (spriteOf, animOf, animFrame) and render.js mon drawing where possible. Do not edit battle.js.

## Units and camera
- T = 32 world px per tile. 1 world px = 1 exterior-sheet px. Trainer OW sprites (HGSS 32x32 frames) and PMD mons draw at scale 2 (SS).
- LEVEL = 1 tile of height = 32 screen px. An entity at ground position (x, y) and height z (in px) draws at screen (x, y - z).
- Render the world into an offscreen canvas at 1 canvas px per world px, then blit to the screen with nearest scaling at an integer zoom (default 2; pick 3 when the viewport is large enough to still show at least 24 x 14 tiles). Camera position rounded to whole world px. Same pattern as render.js worldCv.

## Map scale (2x outdoors)
- The exterior sheet is 1x HD art but trainers and mons draw at 2 world px per art px, so the outdoor world is drawn `ADV.OUT` = 2 times bigger: a tile is 64 world px, a level (LEVEL) is 64 px, a prop draws at 2x. Rooms and the Route 4 cave keep scale 1 (the interior sheet is already 2x art). Characters, mons, speeds, hit circles and battle physics are in world px and do not change.
- Data stays in its authored units (px at scale 1; NPC, door and exit cells in tiles). It is multiplied on load: `ADV.chunk` scales prop positions and z, `ADV.scaleWorld` (called from setWorld and, once, at the end of src/adv-save.js) scales world.js spawn, towns, doors and wild. Prop `solid`, `glow`, anchors and sizes are sheet px, multiplied at use by `ADV.dk(def, x)`.
- The scale follows the position: rooms live at x >= `ADV.EDGE` (204800 px), outdoors below it. Ask `ADV.S(x)`, `ADV.Tp(x)` (tile at a position) or `ADV.Tc(c)` (tile of cell column c); `ADV.T` is the outdoor tile only. Tile-defined distances (spawner NEAR / MIN / FAR / SIM, sight, wander radius, online AOI) multiply by the tile; world-px ones (follow, flee 12 x 32, touch, pile-on JOIN 10 x 32, queue spots 7-8 x 32, the fight box 1280 x 960 = 20 x 15 tiles outdoors) do not. `ar.T` is the fight box's tile.
- Overworld zoom: mouse wheel or LB / RB cycles 1x, 2x (default), 3x (`ADVR.zm`, kept in localStorage `advZoom`).
- Sheet density: a sheet (`ADV_TILESET.density`), a material def or a prop def may carry `density` = art px per sheet px: 1 (default) is HD art, 0.5 is clean 2x pixel art (interior.png and the community sheets). Outdoors world px per sheet px = 2 x density, so HD art draws 2x and 2x art draws 1:1; a 2x-art ground tile is 32 world px and repeats 2 x 2 in the 64 px cell. Rooms draw everything 1:1. Saves hold px positions at the scale in `save.sc`; older saves (no `sc`) are converted on load, and the net protocol is version 2.

## Chunks
- Chunk = 32 x 32 tiles. Chunk data:
```js
ADV.chunk(cx, cy, {
  h:    [...1024],   // height level per cell, int 0..7
  mat:  [...1024],   // ground material index into the world palette (grass, path, sand, water, ...)
  over: [...1024],   // overlay material index or 0 (tallgrass, flowers, path decal)
  kind: [...1024],   // 0 normal, 1 stairsN, 2 stairsS, 3 stairsE, 4 stairsW, 5 ledgeS, 6 ledgeE, 7 ledgeW, 8 bridge deck
  deck: [...1024] | undefined, // bridge deck level where kind == 8
  props: [[name, x, y, z?], ...], // prop instances, world px of the anchor (foot) point
});
```
- Palette lives in `ADV_WORLD.palette = ['void','grass','path','sand','water','tallgrass', ...]` (index 0 = none).
- Loading: inject `<script src="data/adv/chunks/cx_cy.js">` for every chunk within 1 chunk of the camera's chunk; unload chunks further than 2 away (free their caches). Missing chunk = void (solid, drawn black).
- Autotile on load (and re-run for the 1-cell border of neighbours when a neighbour arrives): each material with a 13-tile set picks C, N, S, E, W, NE, NW, SE, SW (outer) or iNE, iNW, iSE, iSW (inner) from its 8 neighbours "same material". Cache the resolved tile ids per chunk.

## Terrain drawing and depth (the core rule)
- Cell (c, r) with height h: its top surface draws at screen y = r*T - h*T. If the cell in front (c, r+1) is lower (hf < h), draw a face of (h - hf) tiles below the top, from (r+1)*T - h*T to (r+1)*T - hf*T, using the cliff face set (L / M / R chosen by whether the left/right neighbours also have a face; top row of the face uses `faceTop`, others `face`).
- Side rims: a plateau cell whose E/W/N neighbour is lower draws the cliff rim tile on that edge (from the cliff set).
- Base pass: all level-0 tops (and their overlay), drawn first, no sorting.
- Row strips: for every visible row r, one drawable containing that row's elevated tops (h > 0) plus every face that belongs to that row's cells. Sort key y = r*T.
- Entities and props: sort key y = foot ground y, tiebreak z. Painter order = ascending key; strips sort before entities of the same row because strip key is the row's back edge.
- This gives correct results for: walking behind a cliff (feet hidden), standing on top, standing in front of the face.
- Bridge decks (kind 8): a separate drawable per deck cell row with key y = r*T and z = deck*T. Comparator special case: entity vs deck of the same row orders by z (entity on top if entity.z >= deck z); otherwise by y.
- Tall grass overlay: draw again over an entity's lower 40% when the entity stands in tallgrass at ground level (wading look). The overlay tile is the same tile, clipped.

## Tileset schema (contract between the tileset builder and the engine)
```js
window.ADV_TILESET = {
  file: 'assets/adv/exterior.png', T: 32, cols: 8,   // tile id = row * cols + col
  // 13-tile sets. Any missing role falls back to C.
  mats: {
    grass:     { C: [ids...] },                       // C may be a list: picked by a hash of (x, y) for variety
    path:      { C, N, S, E, W, NE, NW, SE, SW, iNE, iNW, iSE, iSW, overlay: true },  // overlay = edges are transparent, draw over the base grass
    sand:      { ... }, water: { ..., frames: [[ids for frame 0], [frame 1], ...] }, tallgrass: { ..., overlay: true },
  },
  cliff: { rimN, rimE, rimW, rimNE, rimNW, faceTop: { L, M, R }, face: { L, M, R }, stairsN, stairsS, stairsE, stairsW, ledgeS, ledgeE, ledgeW },
  props: {
    pineTree: { sx, sy, sw, sh,      // source rect in the sheet, px (not tile-aligned)
                ax, ay,              // anchor (foot) point inside that rect, px
                solid: [x0, y0, x1, y1] | null }, // ground-plane rect relative to the anchor; null = walk-through
    ...
  },
};
```
Baked grey shadows in the sheet become translucent black at build time (the builder writes a processed PNG). The engine never reads pixels.
- Animated props: a prop def may carry `frames: n, fps`; frame k is the source rect shifted right by k * sw (src/adv-render.js propFn, out of step per instance). The wind turbine is 4 frames of 56 x 200.
- `ford` is a walkable shallow-water material (not in `world.water`, grouped with the water mats so it autotiles seamlessly): the player walks at 0.55 speed on it (adv-scene.js). Wild ground spawns skip `pavingStone` and, in the Goldacre zone, `path` (adv-wild.js ok()).

## Movement and collision
- Ground-plane movement in world px. Entities have a foot circle (player r = 6 px).
- Axis-separated moves with wall sliding (move x, test, move y, test).
- A move into cell B from cell A is allowed if: B is not void/water/solid; and heights match (hA == hB), or A or B is stairs connecting the two levels in the movement direction, or B is a ledge drop in the movement direction (one-way down: play a hop, z arcs down over 0.3 s, input locked meanwhile).
- On stairs z interpolates linearly across the stair cell between its two levels.
- Bridges: an entity on a deck stays at deck level while crossing deck cells; an entity at ground level under a deck walks below (deck does not block ground level).
- Props have `solid` rects (ground-plane px relative to the anchor); test the foot circle against them.
- Query API for later battle use: `ADV.heightAt(x, y)`, `ADV.blocked(x, y, z, r)`, `ADV.cellAt(x, y)`.

## Player and follower
- Player = HGSS OW sprite from `TRAINER_OW` (4 rows down/up/left/right, 4 frames). Diagonal facing uses an 8-row sheet when the sprite has `rows8`; otherwise diagonal movement shows the left/right row.
- Walk speed 96 px/s, run (hold B / Shift) 160 px/s. Walk cycle frame order [1,0,3,2]-style from TRAINER_OW, idle = stand frame.
- Follower = lead mon (PMD sprite, `drawMonSprite`-style, 8-dir rows). It eases toward a breadcrumb point 1.75 tiles behind the player (`ADVF.FD`, never closer than `ADVF.MIN` = 1.1 tiles, so it brakes when you stop). Walk vs Idle comes from its real speed with hysteresis (0.15 s hold) and facing turns one 45 degree step at a time (`src/adv-follower.js`, pure and tested in `tools/adv-check.mjs`).
- After 2 s of standing still it lives on its own (`AdventureScene.folIdle`): looks around, strolls to a flower (Eat), tall grass, water edge, sign or NPC within view and comes back, hops when happy, sleeps after a long idle or at night. Strolls use `ADV.move` collisions, stay on the player's level and inside the player's building, and end the moment you move. Local only: nothing is sent online.
- A / E facing it (within 2.6 tiles) opens the talk box with a line from the mood model (`ADVF.mood`: HP, status, friendship, level, `save.f.events` ring of the last 10 events with timestamps that fade, weather / time / biome / indoors) and its emotion portrait. Lines and portrait emotion lists are in `data/adv/follower-moods.js`. The world has no weather yet: `?weather=rain|snow|sun` pins one for the mood.
- Both get a soft ellipse shadow on the ground under their foot (at ground height, not at z).

## W1a: battles in the world (1v1, seamless)
Goal: walking into a wild mon turns the spot you stand on into the arena with no screen change. The existing battle sim (src/battle.js) runs unchanged except for small hooks.
- Fight box: on start, build `arena = { world: true, ox, oy, w, h, wall: 0, lv, obstacles: [], spawns, ... }` = a box of 40 x 30 tiles centred between the two mons, clamped to loaded chunks. Battle coordinates are LOCAL to the box (local = world - (ox, oy)), so every existing `ar.w / ar.h / ar.wall` use keeps working. `lv` = the fight level (the partner's cell height).
- Walls: a local cell is solid if its world cell height != lv, is water or void, or is a deck cell. `clampToArena` gets a world branch: when `B.arena.world`, resolve against that solid mask with axis-separated sliding from the entity's previous position (store `e.px, e.py` before movement in updateSide; for calls without an entity just push the point to the nearest open cell centre). Projectiles die when they enter a solid cell whose height is ABOVE lv (they fly over water and lower ground).
- World props inside the box with a solid rect become `B.rocks` entries `{ x, y, r, hp: Infinity, world: true }` (r from the solid rect). They block movement and shots exactly like arena rocks, never break, and are not drawn by the battle (the world draws them).
- Rendering: split render.js `drawWorld` into `drawFloor()` (decals, puddles, rays, hazards, field fx, marks, areas, shadows), `battleSortItems()` (the depth-sorted list it builds now) and `drawOver(dt)` (beams, fx, lighting, impact, laser tells, aim chevron, wheel, weather). Arena mode calls them in the same order as today (zero visual change, confirm with a before/after screenshot). World mode: `ADVR.draw` gets `opts = { floor(g), over(g), cam, zoom }`; floor runs after the base terrain pass, over runs after the sorted pass; battle items are added to the ADV sorted list with world coords (local + ox/oy). Lighting/vignette/rays that assume an arena image are skipped in world mode.
- Camera: battle camera logic (updateCamera) clamps to the box; world draw uses its x/y, zoom = ADVR zoom.
- Flow (AdventureScene): states 'walk' | 'battle'. A test wild mon (PMD sprite, idle wander) stands in the test world. Touch it (or it touches you) -> startBattle with the follower's party as side 0 (positions = the follower's and the wild mon's current spots) and the wild mon as side 1 (cpu tier from its level band). The player trainer stays standing where they were, drawn as a world item, facing the fight. Battle HUD as in arena mode.
- End: wild faints -> back to walk after the faint anim; the follower walks back to the trainer. Player side all fainted -> fade, respawn at world spawn, party healed. Flee: if the partner is more than 12 tiles from the wild mon for 1.5 s, the fight ends ("Got away safely").
- Do not break arena mode or online: run `ALLOW_MISSING_BEHAVIOUR=1 node tools/sim-check.mjs` and `node tools/net-check.mjs` before and after.

## W1b: living wild Pokemon
- Data: `data/adv/encounters.js` = `window.ADV_ENC = { route5: { day: [[species, band], ...], night: [...], fish?: [...] }, ... }` with band in common 45 / uncommon 30 / rare 20 / nat20 5 (percent weights), extracted from the bible's route and town tables. `data/adv/temperament.js` = `window.ADV_TEMPER = { species: { t: 'aggressive'|'skittish'|'passive'|'territorial', group: [min, max], flies?: true, swims?: true } }` for every species that appears in ADV_ENC (and their evolutions).
- Spawner (src/adv-wild.js): keeps about 10-16 wild groups alive within 40 tiles of each player, none closer than 12 tiles to the player on spawn and never on screen at spawn time; despawns groups beyond 60 tiles. Spawn cell = walkable land of the zone (water for swims species, tall grass preferred for small species). Time of day picks the day or night table (server clock from W2; until then a local clock, 24 real minutes = 1 game day).
- Levels: badge band of the player who triggers the fight (`ADV.player.badges`, 0 for now): 0: 3-8, 1: 10-15, 2: 16-21, 3: 22-27, 4: 28-33, 5: 34-39, 6: 40-45, 7: 46-51, 8: 52-60. Rare +1, nat20 +2. Evolve the species to match the level if its evo level is below it (a Wooloo at 30 is a Dubwool).
- Behaviour (overworld, PMD Walk/Idle, 8-dir): passive wander near home; skittish run away when the player is within 5 tiles; aggressive notice the player within 6 tiles in their facing cone (a "!" emote), then charge and start the fight on contact; territorial only charge if the player comes within 3 tiles of home. Groups move together loosely (boids-lite: cohesion to the group centre, separation 20 px).
- Tall grass ambush: each 32 px walked in tall grass at ground level has a 3 % chance to pop an aggressive wild mon out of the grass 1.5 tiles ahead (rustle + "!"), fight starts at once.
- Pile-ons (same species only): when a fight starts, every member of the target's group within 10 tiles joins the wild side's team queue. One wild mon fights at a time; when it faints, the next queued one runs in from where it stands (sendOut at its world position). Others of the queue wait at the edge watching. Fainted wild mons vanish after the faint anim.
- Trainer: on fight start the trainer steps back 2 tiles away from the fight centre (short walk, not a jump) and watches; never inside the fight.
- Wild side HUD avatar: the wild species' portrait.
- Built (src/adv-wild.js): pure logic in ADVW, driven from adv-scene.js. battle.js hooks: sendOut places a mon at `m.at` (local px) and cpuPickSwap walks `side.queue` in order and never swaps by choice. Debug query: `?at=tileX,tileY&time=night|day|<hour>`.

## W1c: party, catching, growth, saves
- Party lives in `ADV.save.party` (sets like the team builder's, plus hp, status, exp, level, moves, ball, nickname, ot). Adventure never reads savedTeams().
- New game flow (placeholder until the story pass): pick hometown (any town from world.js), pick a starter from every base-stage non-legendary species (search box + sprite grid), level 5 with its 4 latest level-up moves.
- Catching: Y / key C opens the ball wheel when items exist; throwing is automatic from the trainer to the active wild mon (arc + shake x3 anim). Gen 3+ catch formula: a = (3*maxHP - 2*HP) * rate * ball * status / (3*maxHP), status x2 sleep/freeze, x1.5 par/psn/brn; shake checks as in the games. A catch ends the fight; that mon joins the party (or the PC box if full).
- Catch rate, base EXP, growth rate: ADV_DEX has them null. Fill them at build time from the PokeAPI CSVs on GitHub (raw.githubusercontent.com/PokeAPI/pokeapi/master/data/v2/csv/pokemon_species.csv has capture_rate and growth_rate_id; pokemon.csv has base_experience) in tools/build-adv-dex.mjs (cache the CSVs under tools/.cache).
- EXP: Gen 5 scaled formula on every KO for every party mon that fought (sent out at least once), split equally. Level up: stats recalc keeping HP fraction; learn level-up moves (if 4 known: prompt to replace or skip); evolve at the end of the fight when conditions are met (level, friendship, time, item use from the bag).
- Bag: balls, potions, status heals, revives, TMs, key items. Item wheel in battle (W1c) with a shared 6 s cooldown, trainer briefly "busy".
- Money: trainers pay on defeat; blackout costs half the money.
- Save file: menu items Save (downloads `kenora-<name>-<date>.sav`) and Load (file input). Content = JSON of ADV.save, encrypted with AES-GCM (Web Crypto) with a key derived via PBKDF2 from a constant game secret plus a per-file random salt, then base64; the GCM tag is the tamper check (edited files fail to load with a clear message). Web Crypto needs a secure context: works on https (GitHub Pages) and http://localhost; on file:// fall back to the same format with a JS AES implementation only if crypto.subtle is missing.

## Art policy and QA gate (2026-10-15)
No script-drawn art. The exterior sheet is the original Chaotic sheet plus community sprites appended below the tiles (tools/adv-build-community.py, catalogue tools/adv-community-items.py; credits in data/adv/credits.js). 2x community art gets `density: 0.5` per def, so one art pixel is 2 world px outdoors everywhere. Rooms draw the 2x interior sheet 1:1, so exterior 1x props used in rooms are copied there doubled (`<name>2x`, EXT2X in tools/adv-build-interior.py, picked by tools/adv-build-rooms.mjs). No baked shadows: pixels with alpha < 200 and RGB max <= 48 become transparent in all builders. Build order: tileset (runs the community builder), interior, rooms, then tools/adv-gen-region.py. The gate is `py -3.12 -I tools/adv-tile-lint.py` (docs/TILE-QA.md): zero errors required.
